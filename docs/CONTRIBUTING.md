\# CONTRIBUTING.md



Version : 1.0

Status  : Official



\---



\# Welcome



TrailBook に興味を持っていただき、

ありがとうございます。



TrailBook は

「GPXライブラリ」を作るプロジェクトです。



しかし、それ以上に



長く育てられるソフトウェア



を目指しています。



コードだけではなく、

設計・ドキュメント・アイデアも

重要な貢献です。



\---



\# Philosophy



私たちは



速く作ること



よりも



長く育てること



を大切にします。



一時的な便利さより



10年後の保守性



を優先します。



\---



\# Ways to Contribute



TrailBookへの貢献方法



・コードを書く



・バグを報告する



・設計を提案する



・ドキュメントを書く



・テストを行う



・UIを改善する



・翻訳する



・アイデアを共有する



どれも同じ価値があります。



\---



\# Before Writing Code



コードを書く前に



以下を読んでください。



PROJECT.md



ARCHITECTURE.md



CODING\_RULES.md



ROADMAP.md



AI\_GUIDE.md



DECISIONS.md



GLOSSARY.md



コードは

設計書の後に存在します。



\---



\# Design First



設計変更が必要な場合



先に設計書を更新してください。



コードだけを変更しないでください。



\---



\# Small Changes



一度に大量の変更をしないでください。



変更は



小さく



分かりやすく



レビューしやすく



してください。



\---



\# Respect Existing Design



現在の設計には



必ず理由があります。



改善案は歓迎します。



しかし



「新しいから」



という理由だけで



置き換えないでください。



\---



\# Code Quality



以下を重視します。



読みやすさ



保守性



一貫性



設計との整合性



短さより



理解しやすさを優先します。



\---



\# Pull Requests



Pull Request は



一つの目的だけにしてください。



良い例



・GPX Parser 修正



悪い例



・Parser修正



・UI変更



・CSS修正



・README更新



を一度に行う。



\---



\# Commit Messages



簡潔に



目的を書く。



例



Implement GPX Parser



Fix Track Selection



Improve Folder Scanner



Update Documentation



\---



\# Issues



Issueを書く場合



以下を明確にしてください。



期待する動作



現在の動作



再現手順



利用環境



可能ならスクリーンショット



\---



\# Feature Requests



新機能を提案する場合



以下を書いてください。



目的



利用シーン



期待される効果



既存設計への影響



代替案



\---



\# Discussions



意見が異なっても



人ではなく



設計を議論してください。



設計理由を尊重します。



\---



\# AI Contributors



AIによる貢献も歓迎します。



ただし



AI\_GUIDE.md



を必ず守ってください。



AIは



設計者ではありません。



設計を尊重してください。



\---



\# Human Contributors



人間もAIも



同じルールです。



設計書を尊重してください。



レビューを歓迎してください。



改善提案を歓迎してください。



\---



\# Review Checklist



レビューでは



以下を確認します。



□ PROJECT.mdに沿っている



□ Architectureを壊していない



□ Coding Rulesを守っている



□ 用語が統一されている



□ EventBusを守っている



□ 新しい依存が増えていない



□ コメントが適切



□ 保守しやすい



\---



\# Documentation



コード変更時は



必要なら



設計書も更新してください。



コードだけ更新することは避けます。



\---



\# Communication



分からないことは



推測せず質問してください。



提案は歓迎します。



議論も歓迎します。



\---



\# Code of Conduct



TrailBookでは



相手を尊重します。



初心者を歓迎します。



質問を歓迎します。



失敗を責めません。



レビューは



コードを良くするために行います。



人を評価するためではありません。



\---



\# Project Values



私たちが守る価値

未来の保守者を守る
